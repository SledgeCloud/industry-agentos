# AgentOS Ops RFT

Agent OS 静态交互 Demo，包含原 AI Ops、全新 AIOps、知识工坊、在线测评、资产概览及企业管理。HTML / CSS / JavaScript 源码直接保存在 `dist/`，无需安装依赖或构建。

## 离线实验场景模拟与评估对象（2026-11-08）

新 AIOps 与「智能体工作坊 → 评测」的实验新增「单轮执行 / 场景模拟」。选择场景模拟后，填写公共场景提示词（可插入场景、画像、已知事实和行为规则模板）及最大模拟轮次。轮次含首轮，一轮是一条用户消息和对应的 Agent 回复，范围 1–20；所有用例使用同一模拟规则，但以各自输入启动独立会话。用例定义继续保留输入与预期输出，不增加单轮或多轮类型。

实验内「评估配置」只保留评估器、已发布版本和评估对象（首轮回复 / 整段会话），支持按名称或编号搜索。所有选中的评估器共同参与判定：全部通过，用例才通过；至少一个明确未通过则用例未通过；没有未通过但有证据不足时保留待确认，Agent 运行异常单独显示运行失败。输入数据自动按评估器要求提供，用例预期仅用于首轮回复；业务维度映射从业务任务的固定配置继承，不要求在实验中手工选择，未配置的业务维度显示未评估，不否决已有评估器结论。没有通过标准的纯分析评估器不能用于这类实验。旧运行保留原始判定方式和证据，编辑保存采用新规则。

结果详情显示实际轮次、结束原因、模拟用户回复和逐轮 Trace，报告保留当次执行及评分配置快照。编辑只影响后续运行，补跑与问题验证沿用来源记录。当前为页面内存 Mock：提示词和轮次驱动本地演示对话，未调用真实用户模拟模型、Agent、工具或评分服务。

## 结果分析与问题优化（2026-11-07）

新 AIOps 与「智能体工作坊 → 评测」同步提供「结果分析」AI 功能按钮。选择已完成的全量评测记录后自动打开评测助手并发送分析请求：新 AIOps 位于右侧，工作坊使用工作台左侧的现有对话区。分析完成后才提交 AI 问题；单纯执行、刷新或查看报告不会自动生成问题。保存 Agent 输出或评估结果标注则立即生成「手工标注」问题，编辑同一标注更新同一问题，不与其它输出或独立对话混用。

问题列表保持单行，分列展示编号、名称、来源、状态、评测记录、关联用例和问题根因，移除负责人。状态为「待修复、待验证、验证完成、已关闭」，通过状态列的多选筛选控制列表，不再提供原未解决/全部类型下拉。操作随状态变化：待修复可修复，待验证可验证或重新修复，验证完成可查看验证详情、重新修复、再次验证或关闭，已关闭可重新打开；关联用例可打开定义。问题详情顶部使用有边框与主次区分的操作按钮。问题修复自动向助手发送对应问题及输入、预期、实际和建议。问题详情使用固定状态总览和双栏布局，左侧为可复制的问题根因、优化建议及验证记录，右侧保留原始输入、预期与实际结果；不再展示每次发现证据和处理记录。

问题验证使用独立验证编号和执行记录，与全量评测和用例补跑分开保存，不进入用例结果、评测记录选择、用例统计或评测报告，也不改写首次全量结果。验证期间保留待验证状态并显示执行进度；完成后进入验证完成，记录通过或未通过结果。验证详情复用对话、Trace 和评估器布局，以独立的验证标题与编号展示，打开时保留问题优化页。详情顶部的「优化用例」下拉提供「新增用例」和「优化关联用例」。新增用例带入原始输入、附件及预期结果，用户需选择当前 Agent 的评测集和任务维度，可编辑后保存或发布，并保留来源问题信息；优化关联用例编辑当前定义，保留原用例编号、发布历史和原始评测证据。问题根因和优化建议使用不同图标与背景；验证记录按独立条目展示状态、时间、评测记录、执行次数及详情入口。

当前分析、对话和修复为本地 Mock 演示，未接入真实模型，修复不会修改实际 Agent 配置；验证使用本地执行器，可能未通过。问题、标注和对话仍为当前页面内存数据。专项：`tests/check-workshop-issue-lifecycle.js`、`tests/check-workshop-optimization-assistant.js`、`tests/check-workshop-issue-review.js`、`tests/check-workshop-experiment-ledger.js`；原生流程由 `tests/check-aiops-evaluation.js` 验证。

用例结果详情：未通过结果提供「结果分析」与「重新执行」，运行失败结果提供「重新执行」。分析只处理当前这次结果；重新执行启动独立对话并保留原结果。问题验证详情不提供这些用例执行操作。

## 评测实验功能按钮与结果复核（2026-11-07）

新 AIOps 与「智能体工作坊 → 评测」共用本次优化。实验标题区的功能按钮随页签变化：实验配置显示「编辑」，实验报告显示「导出」（独立 HTML 报告），用例结果在未执行时显示「执行」，执行后显示「重新执行 → 失败用例补跑 / 全量评测」，问题优化不显示功能按钮；执行中可暂停，暂停后继续。全量评测次数决定本次生成多少条独立评测记录，每条记录按「每个用例执行次数」展开独立对话。例如 10 条用例、每例执行 3 次、全量评测 2 次，会生成 2 条评测记录，每条包含 30 次用例执行；每次对话使用相同用例输入，拥有独立会话与消息，轮次只表示对话内的一问一答。失败用例和指定用例重跑作为原记录的补跑，不增加评测记录数，不替换原输出或原报告。用例结果页右上方选择评测记录，下方始终展示该记录的全量结果，不提供结果范围下拉，也不展示重复的处理进度或冻结说明。补跑证据仍可通过问题台账查看。首次完整全量执行结束后冻结结果、配置、汇总和报告，质量未通过也保留该快照，供后续对比使用；本次不提供对比功能。实验配置页始终展示当前配置，执行结果与报告使用各自的历史快照。时间筛选按全量评测或补跑各自的开始时间统计，补跑不增加评测记录数。

评测实验列表展示用例数、耗时和 Token 消耗；耗时及 Token 为对应记录已执行用例的累计值，未产生结果时显示「—」。用例结果列表的实际结果支持悬停或键盘聚焦查看完整输出，重复执行的输出按次数分开展示，长内容可滚动查看。

新 AIOps 的用例执行结果与问题详情改为无左侧锚点的抽屉，关闭恢复原实验页签、筛选与滚动；其他资源定义保留二级页面。两端结果详情使用同一布局：固定标题栏展示用例主标题和编号，以大字号与状态色突出评测结果，旁边集中展示用例/Agent 版本、评测记录与用例执行定位、独立对话编号、开始/结束时间、耗时与 Token 消耗。正文双栏独立滚动；左侧每轮为一次输入与一次 Agent 输出，显示该轮实际记录的耗时和 Token，预期输出可悬停/聚焦查看；多轮缺失指标显示「—」，不平分总量编造。智能体工作坊右侧继续沿用原评估器评分布局；新 AIOps 右侧按下文的最终通过判定、评估器及可展开明细展示。

Trace 保留层级树、类型和耗时条，每个 Span 默认收起，点击独立展开该 Span 的格式化原始 JSON，可同时展开多项；不再提供输入输出/详情/原始记录切换或底部检查器。切换页签保留展开状态，不同执行结果相互隔离。本地示例的输入、Agent 输出与各本地评分生成明确标注的 Mock 模拟轨迹，耗时为演示值，未调用真实模型或工具；未记录 Trace 时保留空态。悬停/聚焦评估器名称查看执行时保存的评分标准、权重和通过分数，点击可查看评估器详情。

每轮 Agent 输出与每个评估器结果均可标注，统一使用线上会话同款 Tag 图标；打开居中弹窗选择问题类型并填写标注内容。标注按场景、实验、评测记录或补跑、执行结果及具体输出轮次或评估器独立保存，保留编辑记录，不改写原始输出、评分或报告。关闭弹窗返回原结果及滚动位置。输入输出/Trace 页签支持左右方向键、Home/End。

以上仍为页面内存 Mock，刷新恢复示例，标注同样仅在当前页面会话保留。专项验证：`tests/check-workshop-run-model.js`、`tests/check-workshop-record-workflow.js`、`tests/check-workshop-experiment-actions.js`、`tests/check-workshop-result-review.js`、`tests/check-workshop-result-trace.js`；原生详情与功能页签验证继续使用 `tests/check-aiops-evaluation.js`、`tests/check-aiops-page-tabs.js`。

## 新 AIOps 在线评估器（2026-11-05）

从 `dist/new-aiops.html` 左侧「评测 → 在线评估器」进入，支持「手动新建」「Copilot 新建」、查看详情和编辑。手动表单包含名称、描述、关联 Agent、标签、评估粒度、筛选逻辑、评测模型、采样率、评估时间及评估提示词。名称、标签与关联 Agent 同行展示，描述使用紧凑输入区；标签支持回车添加、移除及搜索选择当前范围内已保存评估器的历史标签，未保存草稿不会进入历史。Agent 选项限制在当前企业全景、应用或业务场景范围内，保存后归属所选 Agent 的业务场景。评估粒度为会话、Trace、Span；选择 Span 后可多选本体执行、模型调用、工具调用、智能体、安全围栏。模型选项包含 deepseek 4.1 flash、GPT-6.1 Sol、Claude 5.5 Opus。采样率大于 0 且不超过 100%。评估频率沿用定时任务的「重复」「时间」、周/月日期选择按钮，以及间隔小时和单次执行时间配置，时区为 Asia/Shanghai。

输出支持四种类型：布尔值可指定 True 或 False 为通过值；类别可增删并逐项设置通过或不通过；评分包含评分项、评分标准、正数权重及最终通过阈值，评分范围为 0–100 分，权重合计须为 1，按加权总分与阈值比较；文本输出不保存通过标准。切换输出类型后，仅保存当前类型适用的配置，非 Span 粒度不会保留 Span 类型。Copilot 根据自然语言需求生成可编辑草稿，带入粒度、筛选、模型、采样、调度和输出配置，用户确认完整表单后才创建；取消或未确认的草稿不落库。

配置按场景保存在当前浏览器的 `aiops.online-evaluators.v1` 中，刷新后保留。进入页面默认展示当前范围全部评估器，首次补齐会话、Trace、Span、业务任务四个稳定示例配置，已有配置保留。顶部展示评估器数量、已启用数量、去重评估记录、评估通过率。列表与详情展示启用/停用状态，状态通过专用操作管理，新建默认启用；停用阻止新的手动及计划评估，保留历史记录、运行记录与统计。详情以 `sessionId` 为主键，每个会话一行；会话粒度直接查看结果，Trace、Span、业务任务粒度可按会话二级展开全部对应记录，父级会话数与子级评估记录数分别展示，支持逐条评估详情和完成回复定位。

「业务任务评估器」作为第四种粒度，选择关联 Agent 和业务任务后自动带入任务定义、完成条件、通过标准、评估维度与任务版本快照，生成评估提示词，固定输出任务执行记录。该粒度全量处理符合筛选条件的会话；普通粒度仍支持采样和原四种输出。点击「立即评估」从可见会话内容识别独立任务请求、续办、完成回复和逐项结果，原子写入 `aiops.online-evaluation-ledger.v1`，业务任务页面从同一账本更新记录和指标。执行标识由任务、会话、起始用户消息确定，跨扫描及跨评估器复用，重复扫描不新增计数。CR-1024 演示第 1→17 轮与第 19→21 轮两次独立执行；补充资料不会新增实例。评估器结果保留当次模型、任务快照，运行历史保留配置快照。任务完成率为完成/执行，任务通过率为通过/完成；普通质量通过率为通过/(通过+未通过)，文本和待确认不纳入质量通过率分母。

评估项和提示词配置中的模板按钮改为输入框占位提示；新建标准及提示词为空，占位文案不会进入实际规则，已有标准原文保留。系统组合补充提示词与逐项标准，用户无需维护第二份全局评分规则。新详细版本使用 `decision={type:"evaluation_policy",policyVersion:4,mode,...}`：`weighted_score` 要求每个非文本项配置正权重且合计 1，再用整体 0–100 分阈值判定；评分取原始分，布尔和类别按本项通过=100、不通过=0换算，文本不计，任何参与项缺证／无效均不补零、不生成总分且整体待确认。`custom_prompt` 用提示词定义最终判定，可表达关键项必须通过、部分条件满足等组合规则；系统提供真实逐项结果及声明证据，没有有效的独立最终评审结果时保持待确认。两种方式分别缓存草稿，新增或删除不自动改写用户权重。旧数量配置编辑时转成明确描述原规则的自定义提示词草稿，保存前仍可修改；旧发布版本及历史运行按原快照解释。

评估器支持 `authoringMode: "structured" | "prompt"` 两种配置方式，现有详细配置为默认，旧发布版本缺少此字段时保持原定义。配置方式入口统一在评估项区。两种方式共用名称和描述，编辑器分别保留未保存的详细草稿与提示词草稿；切换不调用模型自动转换规则，保存仅提交当前方式，取消不写入库。提示词配置只有一个带占位提示的“评估提示词”文本框，不再配置评估项、权重及汇总门槛；`method.prompt` 原文逐字保存。系统内部固定 `overall_verdict` 整体判定协议，true 为通过、false 为未通过、null 为待确认，并记录理由与证据。它是平台兼容字段，不作为用户配置的评估项展示，也不从自然语言猜出多指标或评分阈值。提示词没有标准输入变量时自动带入实际输出；显式使用变量时严格校验引用、缺证及消息／轨迹完整性。提示词评估器继续使用实验／在线任务选择的评估模型，并可参与实验的评分／自定义最终判定。配置方式和标准保存在不可变版本与运行快照中，详情及报告展示原提示词与整体结论。

历史 V3 使用 `item_summary` 与评分子项，继续从固定快照按原规则运行和展示。编辑含子项的旧评分时，原子项 ID、名称、标准、权重及阈值只读保留；新直接评分标准需明确重配并确认，不能把旧子项分数／权重静默等同直接总分。布尔、类别和文本标准按原含义保留；旧数量门槛转成明确的自定义提示词编辑稿。旧 V1／V2 的低值数值、区间、总分门槛同样不盲目迁移。整体加权或自定义通过仍保留失败单项，业务维度及问题验证依据对应单项的真实结论。

离线实验与在线任务对多个评估器使用独立的最终通过判定，新建和编辑只提供评分、自定义，通过判定位于评估器配置上方。评分模式在各参与评分的评估器行内填写权重；自定义模式隐藏权重，切回评分时恢复原值。新配置分别保存在 `execution.evaluatorSummary` 与 `passPolicy`，采用 `{type:"composite_policy",policyVersion:1,mode,...}`。评分需逐绑定设置正权重且合计 1，设置整体通过阈值；只有评估器自身 `weighted_score` 的实际 0–100 总分直接计分，其余按最终通过=100、未通过=0换算，旧版数值不盲目当统一分。仅观察不参与；缺证、非法输出及执行异常不补零或重分权重。复杂组合条件由自定义提示词表达，系统使用本次真实评估器结果进行独立最终判断。删除绑定不自动重分权重；原数量策略编辑时转为自定义草稿，冻结历史仍按原语义解释。在线业务任务的每个适用评估器集合都要能使用该权重，集合不兼容会明确定位任务并拒绝保存。

自定义最终判断仅使用系统提供的真实 `evaluatorResults`，通过独立的 `aiops.composite_verdict.v1` 协议返回结论；没有有效且匹配本次证据、策略、模型、对象及运行的结果时保留待确认，不读取 Agent 输出中的假结论。全部评估器为规则校验时，选择自定义仍需评估模型。实验结果保存 `evaluatorPolicyResult` 与 `evaluatorFinalJudgeInputSnapshot/evaluatorFinalJudgeResult`；在线对象结果保存对应 `policyResult/finalJudgeInputSnapshot/finalJudgeResult`。每次独立用例或在线对象分别判定，不跨对象凑数。旧 all/at_least 定义、历史结果及冻结快照保持原语义。整体通过仍保留失败评估器和评估项；独立问题验证依据原问题对应条件。

新 AIOps 查看用例执行结果时，抽屉最大 1440px，左侧实际结果／Trace 与右侧评估结果按约 56:44 分栏。原预期输出按钮移到 Tab 行最右侧，保持 Hover／键盘浮层及轮次对应，删除“对话记录”和“一问一答”冗余行。右侧顶部突出最终判定，显示整体方式、实际结果及各评估器的版本与结论；下方每张评估器卡片首行统一显示名称、版本和结果标签。评估项默认展示真实分数、分类或布尔结果及自身判定，文本仅观察。最终卡片、每张评估器卡片各只有一个“判定记录”，用一层文字说明分数、权重、门槛或自定义标准如何得到结论，不再嵌套快照、证据或标准下拉。缺证与非法输出保留待确认；底层运行配置、标准及历史证据继续冻结，工作坊与两个备份评估器不变。

新保存的评估器由系统维护输入契约。V4 使用 `x-aiops-evidence.version:3,source:"evaluation_policy"`，逐项依赖包含共同补充提示词，最终自定义依赖单独记录。`itemResults` 由系统从实际评估项结果构造，禁止外部输入映射伪造；最终评审输入快照与 hash 绑定标准、模型及参数、评估器版本、对象快照和真实结果。`actual`、`input`、`reference`、`messages`、`trajectory`、`taskDefinition`、`context` 沿明确模板变量自动映射，不从自然语言猜测；提示词配置无变量仍默认实际输出。旧 V3 使用 version:2 的逐项／子项依赖，历史完整性规则保持。会话及轨迹完整性按运行层选中的对象检查，参考答案缺失不使用实际输出替代。

评测任务单独配置场景、Agent、Session / Trace / Span / 业务执行粒度、筛选、就绪条件、稳定采样和运行日程，固定引用已发布的评估器与业务任务快照。常规运行从任务创建后新增或更新的对象开始增量评估，编辑与启停保留该起点；历史补评单独选择时间范围，按对象自身时间使用左闭右开区间，不改变常规任务配置。不再配置回看时间、结果用途、输入路径、时区或每批最多对象数。实际输出、会话消息、执行轨迹和业务任务定义按评估对象自动接入，在线参考答案缺失时不使用虚构数据。每次运行保留模式、配置和原始证据；先排除已处理的对象／绑定快照再选取待评数据，新证据追加结果；停用不会删除历史。

新 AIOps 专用桥接将业务任务的结构化输入、输出、完成条件、稳定维度编号和推荐绑定存入独立关联数据。评测集保留集内用例覆盖关系与任务／用例快照；详情页不再展示额外的固定版本与评估绑定覆盖信息区或手动更新快照按钮。新建离线实验使用统一评估器的固定版本、输入映射、任务／维度映射以及参与验收或仅观察角色。只有覆盖该业务任务与维度的用例才运行相应绑定；维度结果来自统一 Assessment。证据不足、缺少必测维度映射及仅观察均不冒充质量通过或失败，不生成业务质量问题；运行数量、质量通过率和运行异常分别统计。原有实验历史继续使用原快照。

模型配置归属于运行：统一评估器只保存评分标准和提示词，不再配置模型及调用参数。离线实验分别配置被测模型和评判模型；被测模型默认沿用所选 Agent 版本，也可显式覆盖。版本未记录具体模型时保留继承关系并显示未记录。在线评测任务只选择评判模型，被测模型从原会话及调用记录读取，支持多模型，缺失信息明确标为未知。离线实验页面使用“评测执行模型”和“评估模型”标签，默认沿用 Agent 配置模型，仅在选择更换时显示模型选择；表单移除说明性段落与字段提示。模型选项展示真实名称，旧配置与历史快照保持原身份。规则评估无需评判模型。运行记录及 Assessment 分别冻结 `agentRuntimeSnapshot`、`judgeRuntimeSnapshot`；后续修改配置不会回写历史，实际生效的评判模型与参数参与评估配置哈希和去重。

## 在线评测任务交互（2026-11-09）

新 AIOps 的「评测任务」统一显示为「在线评测任务」，保留原内部路由。创建与编辑依次为：基本信息与评估对象 → 运行方式 → 筛选与采样 → 评测时机与重评 → 通过判定 → 评估器。先决定运行方式，再展示该方式适用的数据选择配置；事件条件与定时计划归入运行方式，Span 类型限制归入手动／定时的数据筛选，顶部锚点与表单顺序一致。自动触发第三节仅显示采样；业务任务的手动／定时第三节为会话筛选与采样。筛选使用随对象变化的字段、运算符和值，支持全部满足或任一满足。对象状态、关键词统一作为筛选条件，不再提供重复的独立字段。名称默认使用不区分大小写的“包含”匹配，选择“等于”才要求完整一致；Trace 名称取自身记录，所属会话名称单独筛选。业务任务的筛选字段及采样单位均为候选会话，先筛选与采样，再判断评测时机，运行时才识别业务任务。旧配置的状态与关键词限制在编辑时显示为条件，保留原有与／或关系。

选择「业务任务」后，通过可搜索的下拉框多选任务定义。多选任务是候选集合，至少命中一项后评测；所选任务全部未命中时，按本轮明确规则直接生成“业务任务未命中”的最终不通过结果，不伪造评估器输出。无法识别或识别服务不可用仍为待确认。评估器通过可搜索下拉选择，固定版本独立配置，默认适用于上方所选全部业务任务；仅在可选的专属范围与维度映射中指定某个业务任务。页面移除「数据预览」入口和展示区；内部只读候选查询仍供模拟事件关联对象使用。

任务级通过判定与实验统一采用评分、自定义两种方式，默认评分阈值 80。文本等仅观察的绑定不进入权重；全部绑定仅观察时，整体保持仅观察。最终对象结果按实际策略展示。策略、对象证据及评估器引用随运行冻结，改门槛不回写历史，未变化的单个评估结果可复用后重新计算对象最终结论。历史只有单个评估器结果的运行继续展示原始记录，不补造历史结论。

运行方式包含手动、定时批量和自动触发。自动触发可选择对象新增或更新、用户点踩、上游负面情绪信号及评估结果满足条件；事件来源和最终评估对象分别关联。「就绪条件」改称「评测时机」，与运行方式放在一起：手动只处理本次满足条件的对象，定时每批处理满足条件的增量对象，自动事件则等关联对象满足时机后送评；均可选择当前快照、结束后或空闲后。更新重评配置明确区分首次评测与证据更新后重评，重复扫描及同一事件去重，新的反馈事件可触发对已有对象的独立评测，历史配置、触发原因和证据快照保留。任务详情提供本地“模拟触发”以检查事件交互。

手动与定时批量使用常规数据筛选；自动触发由事件定位对象，保留事件条件、评测时机、采样和通过判定，不再展示或执行“附加数据条件”，Span 类型等常规数据限制也不在自动模式生效。场景、Agent、评估对象类型及所选业务任务范围始终生效。原有筛选配置保留用于切回手动或定时批量，自动模式不会应用这些保留条件；运行快照记录本次实际使用的事件或筛选范围。采样默认 100% 为全量。筛选确定批量候选范围，评测时机控制对象何时可送评。

上述新增能力仍运行于本地 Mock：自动触发随页面运行，负面情绪使用上游传入信号，任务识别与评估不代表已接入生产模型或后台事件服务。

在线任务创建与编辑表单移除解释性段落、字段下方提示、流程框及底部存储说明，保留字段与选项、已选状态、资源版本、校验错误和失效范围警告。表单六段顺序、搜索选择、模式切换及通过判定逻辑不变；评估器资产编辑及结果证据仍按原方式展示。

新 AIOps 开启独立的在线任务演示目录，按当前可用场景、Agent 和业务任务补充会话、Trace、Span、业务任务示例，覆盖手动、定时、事件触发、采样、启停及评分／自定义策略。示例运行保留原始 Mock 证据、评估器与任务版本、单个评估器结果和对象最终判定。每次打开或刷新都从固定 V2 目录初始化，不读取浏览器缓存；同一页面内的编辑、删除及运行状态在切换功能时保留。示例生成不调用真实模型，也不发送正常运行回调。

新 AIOps 初始化时，用这 8 个新版实验替代原来 6 个未改动的工厂实验，默认实例的配置与运行结果统一采用评分或自定义判定，不再混入旧数量判定或缺少统一评估记录的样例。仅替换本次由共享工厂新建且内容未改动的对象；已有实例、用户改动和真实历史不按编号清除。智能体工作坊保留原样例。

推荐演示顺序：

1. 在评测实验打开「渠道分货上线验收」或「采购寻源上线验收」，从用例结果查看正常输出、错误输出和原始证据。
2. 到「问题优化」筛选「商品编码缺失时暂停分货」（销售）或不合格供应商相关问题（采购），执行修复、验证，查看验证详情，再关闭问题。原运行结果保持不变；新一轮运行读取修复后的业务输出。
3. 使用规则冲突或过期准入样例演示验证仍不通过，用缺失库存/交期回执样例演示待确认。「交付质量与依据加权评估」与采购对应实验预置待验证、验证完成和关闭等状态。
4. 运行尚未执行的「边界场景稳定性回归」或「异常场景稳定性回归」，演示多次独立执行、批次和自定义组合规则。打开风险多轮综合复核实验，查看澄清前后回答及自定义综合判定。
5. 在线任务打开「销售交付质量加权巡检」，执行增量评估，查看新对象及最终判定；再次执行验证未变化对象不重复送评。使用「用户点踩整体质量复评」的「模拟触发」演示反馈事件。

业务答案不包含自报分数。模拟评估服务独立返回有类型的评估结果，并校验输入、参考答案、附件、用例版本、评估定义和模型配置；修改示例用例后不会沿用旧答案或旧评分。修复分别覆盖恢复通过、仍然失败、证据不足三种结果，缺证不补零分。评估记录、模型配置、策略及验证证据按运行冻结。

五个评测功能统一使用页面内存 Mock，重复进入保留本页的任务、用户编辑、删除与历史；打开或刷新页面重新加载固定目录、运行结果和修复闭环。不读取旧浏览器数据，也不向本地存储或后端保存。新版依赖和实验快照全部准备成功后才替换旧工厂样例，初始化失败会明确提示，不再静默生成空列表。定时和事件在本地页面中模拟，不代表生产调度或真实模型接入。


## 在线评测会话结果与运行记录（2026-11-10）

新 AIOps 的评估器详情移除“版本记录”Tab，保留发布快照及固定版本引用；详细配置的“补充提示词”统一改为“提示词”。在线评测任务列表将场景独立放在关联 Agent 前，状态放在操作前并可点击启停；“查看”打开可直接修改、保存的当前任务配置，任务自身不提供版本操作。手动评测与定时批量均提供“手动触发”；增量评估、历史补评与删除收进“更多”。

点击任务名称默认进入会话评测结果列表。同一来源会话下的对话、Trace、Span、业务任务合并成一行，列表按各逻辑对象最近一次结果统计对象数量及通过／未通过／待确认／仅观察分布；该分布不替代各对象自身的最终判定。会话详情按对象类型筛选，保留对象判定、评估器结果、指标、证据及历史对象结果。仅有历史评估器记录的对象明确标示未保存最终判定；无法确定来源会话的对象分开展示，不合并为同一会话。支持按会话名称／ID、结果和运行批次筛选。

每次有效手动或定时触发均留下独立运行记录，空运行显示时间范围、已评跳过或采样等处理原因；执行异常与质量未通过分别展示。运行详情提供触发来源、开始／结束时间、耗时、处理数量、模型与任务配置快照，以及仅限该批次的会话结果入口。编辑任务不会回写历史快照。仍为当前页面内存 Mock，刷新恢复预置数据，定时调度依赖页面持续运行，未接入真实评判模型或后台调度。

验证：`node tests/check-online-session-results.js`、`node tests/check-unified-evaluation-ui.js`，以及统一评估数据、桥接、集成与在线任务流程的现有专项检查。
